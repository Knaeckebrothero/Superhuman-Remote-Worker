# Research & Exploration Process

These are default instructions for research and exploration tasks. Follow them unless the user provides specific instructions that override this workflow.

## 1. Understand the Research Focus

- Read the task description and all provided documents carefully
- Identify the core question or area to explore
- Define what a useful outcome looks like (ideas, comparisons, evidence, benchmarks)
- List what you already know vs what needs investigation
- Document assumptions and scope boundaries in workspace.md

## 2. Survey Broadly

- Search across multiple sources: web, academic papers, existing codebase, documentation
- Use varied search queries — don't stop at the first framing of the question
- Collect a wide set of leads before going deep on any single one
- Save promising sources and references immediately — don't rely on memory
- Note patterns: what approaches appear repeatedly across sources?

## 3. Investigate Promising Leads

- Deep-dive into the most relevant sources from your survey
- Extract specific evidence: data, examples, code patterns, benchmarks
- Cross-reference claims across multiple sources for reliability
- Run small experiments to validate feasibility when appropriate
- Cite every factual claim — no citation means no claim

## 4. Analyze the Existing State

- Examine the current codebase, configuration, or data relevant to the task
- Identify gaps, inefficiencies, or opportunities for improvement
- Compare current state to best practices found during research
- Look for patterns that repeat across multiple areas
- Document specific locations (file paths, line numbers) for every finding

## 5. Generate Proposals

- Write up each finding as a structured idea artifact
- Be specific: name files, reference evidence, describe the change
- Include effort estimates and risk assessments
- Identify dependencies and prerequisites
- Prioritize by impact — what would make the biggest difference?

## 6. Document & Synthesize

- Summarize key findings and their relationships
- Organize output files clearly (ideas, experiments, references)
- Update workspace.md with a compressed index of everything produced
- Note dead ends and why they were abandoned (prevents revisiting)
- Ensure all deliverables are in the appropriate output directories

## 7. Self-Assess Coverage

- Review the original task description — have all aspects been addressed?
- Identify remaining unknowns or areas that need further investigation
- Flag ideas that need validation before implementation
- Check that evidence supports every proposal
- Verify no duplicate ideas exist in the output
