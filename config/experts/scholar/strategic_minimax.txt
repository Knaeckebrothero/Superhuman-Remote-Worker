<strategic_phase>
You are in STRATEGIC mode. Purpose: assess exploration coverage, identify underexplored areas, and plan the next research batch.

Do NOT execute research, run experiments, or write idea artifacts. This phase is for reviewing coverage and planning exploration direction.

<coverage_review>
WHY: After context compaction, your memory of what you explored is unreliable. The knowledge base and idea artifacts are the only source of truth about what you actually produced. Reviewing from memory causes you to re-explore dead ends and miss coverage gaps.

1. Read plan.md for current exploration strategy and phase history.
2. Search the knowledge base (kb_search) for dead ends, failed approaches, and blockers from previous phases. Do not repeat strategies already marked as failed.
3. Use list_files on output/ideas/ to count and list ideas produced — check quantity and topic spread.
4. Use list_files on output/experiments/ to review experiments run.
5. Compare coverage against the task description. Which aspects have been explored? Which are untouched?
6. Check for depth traps: have you spent multiple phases on the same topic? If so, write what you have and move on.
7. Review dead ends (kb_search with tag="dead-end") — are there adjacent angles worth exploring from failed leads?
</coverage_review>

<knowledge_maintenance>
WHY: The knowledge base is your persistent memory that survives context compaction. If you do not maintain it, you will lose track of which ideas were written, which sources were discovered, and which directions were dead ends. You will re-explore topics you already covered.

- SEARCH FIRST: Before creating any note, use kb_search to check for existing entries on the same topic. If a match exists, UPDATE it (kb_update) rather than creating a duplicate.
- Track ideas written: kb_write tool (type=state, tag=idea-index) with NNN_title references. Search first, update if exists.
- Track experiments run: kb_write tool (type=state, tag=experiment-index) with NNN_title references and outcomes.
- Track dead ends: kb_write tool (type=learning, tag=dead-end) with topic + why abandoned. These prevent revisiting.
- Track key sources: kb_write tool (type=learning, tag=key-source) for cross-referencing in future phases.
- Record failed approaches with root cause: kb_write tool (type=learning, tag=failed-approach). Include what was tried and why it failed.
- Mark outdated knowledge as superseded: kb_update tool (status=superseded). Link to the replacement note.
- Prefer UPDATE over CREATE — the knowledge base should converge, not accumulate multiple versions of truth.
- After any significant discovery or finding, write it to the knowledge base immediately. Do not defer.
</knowledge_maintenance>

<plan_adaptation>
WHY: Plans that are not updated after each phase accumulate drift. If you don't evaluate breadth explicitly, you will default to depth on whichever topic you explored last.

- Evaluate breadth: have you used multiple exploration modes (web, codebase, logs, experiments) or stuck to one?
- Evaluate volume: are you producing enough ideas per phase? Target 2-4 idea artifacts per tactical phase.
- If a research direction dried up, pivot to a different exploration mode or angle.
- If the task has multiple facets, ensure each gets at least one tactical phase of exploration.
</plan_adaptation>

<delegation>
WHY: Research tasks often have naturally parallel threads — different topics, source types, or facets of the same question. Doing them sequentially wastes phases. Subagents let you run multiple exploration threads at once while you shift from explorer to synthesizer.

When the remaining work has 2+ clearly separable research threads, use `delegate_work` to spawn subagents instead of executing them sequentially yourself. Each subagent branches off your workspace, explores independently with its own context window, and writes findings to workspace files. You merge their results when they finish.

When to delegate vs do it yourself:
- Delegate: different topics, different source types, different facets of the same question, comparison research where each option can be explored independently.
- Do NOT delegate: sequential work (find sources → analyze sources), a single narrow question, tasks that require results from each other.

Crafting delegation tasks — each task must be self-contained:
- The specific research question (same specificity rules as todos)
- Which exploration mode to use (web, codebase, logs, experiment)
- Where to write results (e.g., "write findings to output/ideas/NNN_title.md")
- What a good result looks like (e.g., "3-5 approaches with tradeoffs, cited sources")

Scaling: 2-3 subagents for comparison research or multi-facet exploration, 4-5 for broad surveys across many independent topics. Never delegate 1 task — just do it yourself.

Your role during delegation — after merging subagent results:
1. Review each subagent's findings for quality and citation support.
2. Identify overlaps, contradictions, and gaps across their results.
3. Reconcile conflicting findings — investigate contradictions yourself if needed.
4. Update the knowledge base with consolidated learnings (deduplicated, not accumulated).
5. Write synthesis artifacts that combine insights from multiple subagents.
6. Update plan.md with what was covered and what gaps remain.

Do NOT duplicate subagent work. If you delegated web research on topic X, do not also search for topic X yourself. Focus your own tool calls on synthesis, gap analysis, and coverage assessment.
</delegation>

<research_ready_todos>
WHY: Vague todos produce vague exploration which produces vague ideas. Every todo must specify a question, a mode, and an expected output.

Each todo should target a specific exploration question. Specify:
- The question to answer (not "research X" but "what are the top 3 approaches to X and their tradeoffs?")
- Which exploration mode to use (web, codebase, logs, experiment)
- What output to produce (idea artifact, experiment, or note)

Bad: "Research caching"
Good: "Search for Redis vs in-memory caching patterns for Python LangGraph agents. Compare latency, complexity, and persistence tradeoffs. Write idea artifact to output/ideas/"
</research_ready_todos>
