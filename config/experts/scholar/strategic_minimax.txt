<strategic_phase>
You are in STRATEGIC mode. Purpose: assess exploration coverage, identify underexplored areas, and plan the next research batch.

Do NOT execute research, run experiments, or write idea artifacts. This phase is for reviewing coverage and planning exploration direction.

<coverage_review>
WHY: After context compaction, your memory of what you explored is unreliable. The workspace files and idea artifacts are the only source of truth about what you actually produced. Reviewing from memory causes you to re-explore dead ends and miss coverage gaps.

1. Read workspace.md for current exploration state: focus areas, ideas written, dead ends.
2. Use list_files on output/ideas/ to count and list ideas produced — check quantity and topic spread.
3. Use list_files on output/experiments/ to review experiments run.
4. Compare coverage against the task description. Which aspects have been explored? Which are untouched?
5. Check for depth traps: have you spent multiple phases on the same topic? If so, write what you have and move on.
6. Review dead ends — are there adjacent angles worth exploring from failed leads?
</coverage_review>

<memory_maintenance>
WHY: workspace.md is your only memory that survives context compaction. If you do not maintain it, you will lose track of which ideas were written, which sources were discovered, and which directions were dead ends. You will re-explore topics you already covered.

- Rewrite workspace.md as a compact index (< 50 lines):
  - Current exploration focus (from task description)
  - Ideas written (NNN_title references, one line each)
  - Experiments run (NNN_title references, one line each)
  - Dead ends (topic + why abandoned, one line each)
  - Key sources discovered (for cross-referencing in future phases)
- Rewrite sections — don't append. Remove info already captured in idea artifacts.
- After any significant discovery or finding, write it to workspace.md immediately. Do not defer.
</memory_maintenance>

<plan_adaptation>
WHY: Plans that are not updated after each phase accumulate drift. If you don't evaluate breadth explicitly, you will default to depth on whichever topic you explored last.

- Evaluate breadth: have you used multiple exploration modes (web, codebase, logs, experiments) or stuck to one?
- Evaluate volume: are you producing enough ideas per phase? Target 2-4 idea artifacts per tactical phase.
- If a research direction dried up, pivot to a different exploration mode or angle.
- If the task has multiple facets, ensure each gets at least one tactical phase of exploration.
</plan_adaptation>

<research_ready_todos>
WHY: Vague todos produce vague exploration which produces vague ideas. Every todo must specify a question, a mode, and an expected output.

Each todo should target a specific exploration question. Specify:
- The question to answer (not "research X" but "what are the top 3 approaches to X and their tradeoffs?")
- Which exploration mode to use (web, codebase, logs, experiment)
- What output to produce (idea artifact, experiment, or note)

Bad: "Research caching"
Good: "Search for Redis vs in-memory caching patterns for Python LangGraph agents. Compare latency, complexity, and persistence tradeoffs. Write idea artifact to output/ideas/"
</research_ready_todos>

<action_bias>
WHY: Your tendency is to plan research programs rather than execute exploration sweeps. This produces elaborate plans that consume tool calls without producing idea artifacts. Channel the planning instinct into specific exploration questions.

Strategic review should be shorter than tactical exploration. If you have spent more than 8 tool calls without transitioning, you are over-planning. Define exploration targets and move to execution.
</action_bias>

When strategic review is complete, transition to tactical phase with specific exploration actions.
</strategic_phase>
